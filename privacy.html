Privacy Policy

JARVIS — personal voice assistant. Last updated 28 August 2026.

Who this covers

JARVIS is a personal project used by one person: its author. It is not distributed, sold, or offered to other users. This policy describes how it handles the author's own Google account data, and is published because Google requires a privacy policy for applications that request access to Gmail and Calendar.

What data is accessed

JARVIS requests two Google OAuth scopes, and no others:

  • https://www.googleapis.com/auth/gmail.modify — reading and searching messages, and creating drafts. This scope also permits sending and deleting; JARVIS does neither. It has no code path that sends or deletes mail.
  • https://www.googleapis.com/auth/calendar.readonly — reading calendar events. It cannot create, change or delete them.

Data is requested only in response to an explicit instruction — "check my mail", "what is on my calendar". Nothing is polled, indexed or collected in the background.

Important: message text is sent to a language model

When asked to summarise, explain or draft a reply to an email, JARVIS sends the relevant text of that message — up to roughly 2,500 characters of the body, plus the sender and subject — to the third-party language model that produces the answer. Depending on configuration and availability that is Groq, Google Gemini, or a model running locally on the same computer via Ollama.

This is stated plainly because it is the one place Google user data leaves the machine. It is inherent to how the feature works: a model cannot summarise a message it has not been shown. Their handling of that text is governed by their own policies — Groq and Google. Configuring Ollama as the only provider keeps everything on the local machine.

What is stored, and where

  • OAuth tokens are stored in a single file on the local computer. They are never transmitted anywhere except to Google, and are excluded from version control and from any distributable archive.
  • Conversation history — what was said to JARVIS and what he replied — is stored locally so he can recall earlier context. Where a reply quoted an email, that quotation is part of that local record.
  • Email and calendar contents are not otherwise saved. There is no mail cache, no index and no copy of the mailbox.
  • There is no server, no database off the machine, no account, no telemetry and no analytics of any kind.

What is never done

  • Google user data is not sold, rented or shared with anyone.
  • It is not used for advertising or profiling.
  • It is not used to train any machine learning model.
  • It is not transferred to anyone other than the language model provider described above, and then only as needed to answer the request at hand.
  • No mail is sent and no calendar entry is altered.

Limited use

Use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Retention and deletion

Access can be revoked at any time from Google Account permissions, which immediately and permanently ends all access. Deleting the local token file has the same effect on this machine. Local conversation history can be deleted at any time by the user, and JARVIS has a command to do so.

Changes

Any change to this policy will be published on this page with a new date. Since the application has a single user, changes are not notified separately.
